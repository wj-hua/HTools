# HTools MCP 计划

## 目标

将 HTools 的部分 macOS 能力提供给 HCode 中的 AI 使用。用户可以直接用自然语言提出请求，例如“今天 Codex 用了多少 token？”或“当前连接了哪台手机？”。AI 调用对应工具后，根据实际结果回答。

目前已提供本机只读 MCP 服务，以及用量、进程、待办、设备查询和手机截图；其他能力仍是规划。首要使用场景是本机 HCode，设计应允许以后接入其他 MCP 客户端。配置方法见项目 README。

## 现有基础

- Token 用量已支持 Claude Code、Codex、agy 和 DeepSeek Harness，包含解析、部分重复请求去重、缓存及按时间汇总。
- 进程监控已识别 AI 工具进程并统计内存。
- 任务清单支持标题、备注、截止日期、完成状态和排序。
- 手机调试已有 ADB / HDC 设备查询、截图和应用操作；Stetho 支持 Android 应用抓包。
- HCode 已有 MCP 管理入口，可配置命令形式的服务。各 Provider、会话模式及已有会话是否能使用新工具，需分别验证。

## 能力清单与优先级

工具名称仅为建议，最终以实现时的接口为准。

| 优先级 | 能力 | 候选工具及用途 | 注意事项 |
| --- | --- | --- | --- |
| 高 | Token 用量 | `get_token_usage`：按今天、本周、本月或指定日期查询，返回各工具明细 | 与 HTools 界面使用相同统计口径，注明本地时区和查询时间 |
| 高 | AI 进程与内存 | `list_ai_processes`：查询已识别进程、PID 和内存 | 首版只查询；结束进程后续单独设计 |
| 高 | 任务清单 | `list_tasks`、`add_task`、`update_task`：查询、创建、修改和完成任务 | 需保证 HTools 与 MCP 并发访问时不丢失更新 |
| 高 | 手机设备查询 | `list_devices`、`get_device_info`、`get_foreground_app` | 指定设备；分别核实 Android 与鸿蒙的能力范围 |
| 高 | 手机截图 | `capture_device_screen`：获取指定设备截图，供 AI 分析 | 图片可能包含个人信息；确认客户端能接收图片结果 |
| 中 | Stetho 抓包 | 查询当前会话请求摘要，按需读取详情 | 抓包数据在会话内存中；正文需在停止抓包前读取，可能包含敏感信息 |
| 中 | 蒲公英分发 | 已支持 `upload_to_pgyer`：按明确指令上传 APK/IPA/HAP 安装包，返回链接与二维码 | 密钥保存在 Keychain，支持传参指定，不将密钥暴露给模型 |
| 中 | 常用文本 | 按标签查询、创建和修改文本 | 内容可能包含个人信息；避免无关批量读取 |
| 中 | 翻译与 OCR | 翻译指定文字、识别指定图片中的文字 | 翻译会使用已配置的外部接口；明确数据发送范围 |
| 低 | 散热背夹 | 查询连接状态、温度和模式；设置模式、灯光和定时关闭 | 依赖蓝牙连接及设备状态；现有协议仅在特定型号验证 |
| 低 | 跨设备剪贴板 | 查询同步状态，按请求读取或发送指定内容 | 内容敏感，避免默认读取全部历史或暴露连接凭据 |
| 低 | 防止休眠 | 查询或修改当前系统设置 | 修改需管理员授权，作用于整台 Mac 且会持续生效 |
| 暂不推荐 | Finder 右键菜单、截图标注、实时投屏交互 | 先保留现有界面交互 | 对 HCode 的直接收益暂不明显；后续按实际需求评估 |

手机应用安装、启动、强制停止、清除数据及卸载等能力已有基础，但会改变设备状态；若后续提供，应作为独立工具并明确目标设备和应用。结束进程、删除任务及其他删除操作同样按实际需要单独设计。

## 推荐架构

```text
HCode 中的 AI
    → MCP 工具
    → HTools 能力层
    → 本地统计、任务数据或设备服务
```

1. 提供一个本机 `htools-mcp` 服务，优先考虑标准输入输出传输，由 MCP 客户端启动。具体打包、安装和发现方式在实施时确定。
2. 将可复用的业务逻辑从界面状态中提取，让 HTools 界面与 MCP 调用同一份实现。先复用现有解析、去重、汇总和设备服务，避免在 HCode 中复制逻辑。
3. 对 HTools 已在内存中维护的状态，设计清晰的所有权和跨进程访问方式。任务清单、抓包会话、背夹连接及设备状态不能假定可被独立 MCP 进程直接访问。是否需要由运行中的 HTools 提供本地服务，应按能力逐项确定，并明确 HTools 未运行时的行为。
4. 处理多进程并发：尤其是任务文件的读写和 token 解析缓存的写入，避免覆盖更新或损坏缓存。
5. 工具返回结构化结果和明确错误；只读查询与改变状态的操作分开。敏感内容按请求和必要范围返回，凭据不进入工具结果。

## Token 用量示例

用户问：“今天各个 AI 工具用了多少 token？”

AI 调用 `get_token_usage(period: "today")`，工具返回查询时间、本地时区、总量和按工具划分的输入、缓存读取、缓存创建、输出、推理用量。AI 再据此回答。

“今天”沿用 Mac 本地日历和时区。总量沿用 HTools 当前实现，包含上述各类 token；这是本机记录的统计，不等同于账单金额。无记录、读取失败和数据尚未刷新应能区分，不能把失败伪装成零用量。

## 分阶段实施

### 第一阶段：打通基础能力

- [x] 复用 token 统计逻辑，提供用量查询；MCP 进程不写共享缓存。
- [x] 提供 AI 进程查询。
- [x] 提供只读任务查询，读取已保存的数据。创建和更新需要先解决跨进程同步，留待后续。
- [x] 提供设备列表、设备信息和前台应用查询；多设备时要求指定 ID，指定设备掉线后不切换到其他设备。
- [x] 提供手机截图，以 MCP 图片内容返回 Android 的 PNG 或鸿蒙的 JPEG。
- [ ] 验证截图结果在 HCode 各 Provider 中的展示和识图能力。
- [ ] 在 HCode 实际使用的 Provider 中配置服务，验证工具发现、调用、错误返回及会话重启后的行为。受限会话是否开放这些工具需单独决定，不假定普通会话的配置自动适用。

### 第二阶段：按实际需求扩展

- [x] 接入蒲公英分发上传（`upload_to_pgyer`），支持 APK/IPA/HAP，自动记录至本地历史。
- 接入手机截图和 Stetho 抓包查询，并明确数据范围及会话生命周期。
- 按需求接入常用文本、翻译和 OCR。
- 根据设备控制、背夹、剪贴板和休眠功能的实际使用频率，逐项决定是否接入。

## 验收要点

- HCode 中的 AI 能发现并调用已启用工具，回答基于真实结果；服务不可用或权限不足时明确报错。
- 同一时间范围的 token 结果与 HTools 界面一致，注明时区和刷新时间。
- HTools 与 MCP 同时使用任务和统计缓存时，不丢失更新；重启后的数据一致。
- 多设备场景不会误操作未指定的设备；截图和敏感数据仅按请求返回。
- 会改变系统、设备或外部服务的工具遵循明确的用户指令，并反馈实际执行结果。
